Claims and patients

The claims list, the claim record with its tabs, the editor used for reviews and corrections, the modals that change a claim's state, and the patient record used to fix coverage. The main example is Hart, J. at Willamette Ortho, whose line 2 was denied by Cigna.

C-01

Claims list

PageMVPRoute /claims
Purpose
Find any claim and work lists of claims by state, age or deadline.
Data
claims joined with patients (last name, first initial), clients, payers, current claim_version totals, latest claim_events row; counts per saved view.
Actions
  • Saved view tabs switch the filter set; counts per tab.
  • Search by patient name, patient control number or payer claim number.
  • Filters: client, payer, status (multi), mode, DOS range.
  • Columns popover (shown) toggles and orders columns; saved per user.
  • Row click opens C-02. Selecting Ready claims enables "Release selected" (C-17).
  • Export: CSV of non-PHI columns for billers; admins may include patient names (re-auth, audit-logged).
States
Loading: table skeleton. Empty view: "No claims in this view" with link to All open. Search with no results suggests checking another client filter. 10,000+ rows: server pagination, counts shown as estimates over 10,000.
Rules
Status chips use the shared vocabulary for every claim state (Draft, Built, Needs review, Blocked, Ready, Submitted, Accepted, Rejected, Paid, Partially paid, Denied, Corrected, Reversed, On hold, Closed, Voided). Default sort balance descending within the view.

C-02

Claim detail: summary

Page tabMVPRoute /claims/:id
Purpose
One place to understand a claim's state, why it is there and what to do next.
Data
Header: claims, current claim_version, patients (last name, initial, age), payers, clients, totals from remit_claims. Body: open work item for the claim, latest scrub_results (confidence, findings, ai_summary), latest denial codes with suggestion, last 4 claim_events.
Actions
Header actions change by status: Needs review → Release (C-11), Edit (C-08), Hold (C-12); Rejected or Denied → Build correction (C-09); Submitted or Accepted → Check status (C-15); any open state → Write off (C-14), Void (C-13), Add note (C-16) in the more menu. Suggestion: Build correction with this fix opens C-09 with the fix applied; Dismiss records the choice.
States
No open work item: denial card replaced by a status summary ("Accepted by Cigna, usually pays in 17 days"). Filing deadline within 14 days: amber deadline figure and banner. Voided or closed: read-only, actions hidden except Add note.
Rules
Viewing a claim detail is audit-logged. Patient shown as "Last, F." here; full name and DOB on C-06 behind reveal. AI text always labeled Suggested with evidence.

C-08

Claim editor

PageMVPRoute /claims/:id/edit
Purpose
Change any part of a claim and see the result of the checks as you type.
Data
Current claim_version payload (canonical 837 shape), providers and locations for the client, coverages, payers; scrub preview via POST /api/claims/:id/scrub (no save).
Actions
Edit fields; Add or remove diagnosis or line; Save draft (new draft version, no release); Save and release (save, scrub, release if no block findings, otherwise stay with findings shown); Discard (confirm if changes). Keyboard: ⌘S save draft, ⌘Enter save and release.
States
Changed fields carry .changed highlight. Scrub re-runs 400 ms after typing stops; meter shows skeleton while running. Block finding present: Save and release disabled with reason. PM write-back unavailable for this client: footer says "will create a task to update Tebra".
Rules
Each field change becomes a corrections row on save. The footer lists every change in plain words. Member ID masked unless revealed. Codes only, no descriptions.
