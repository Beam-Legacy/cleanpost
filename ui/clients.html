Clients

Each client is a practice the billing company serves. These views show how every client is doing, hold its settings, and let an admin change how its claims and payments flow.

CL-01

Clients list

PageMVPRoute /clients
Purpose
See every practice the billing company serves, how each is performing this month, and which need attention.
Data
clients (name, status, default_mode), connections (adapter_key, status), month-to-date claims released, first-pass acceptance and automation rate from report rollups, open work_items count per client.
Actions
  • Row click opens the client overview (CL-02).
  • Add client opens the onboarding wizard at O-01.
  • Status and PM filters; search by client name.
  • Sort by any numeric column.
States
Loading: table skeleton. No clients yet: empty state "Add your first client" with the wizard button. Onboarding clients show their wizard step instead of figures and link back into the wizard.
Rules
Billers see only clients in their client scope and do not see Add client. Health dot: green healthy, amber degraded or manual operations pending, red failed (failed connections sort first).

CL-09

Change mode

ModalMVP
Purpose
Switch how a client's claims leave and payments come back, with the consequences spelled out first.
Data
Current mode, modes the adapter supports (capabilities), in-flight claims by mode, per-payer ERA enrollment status, whether the adapter supports markChargeBilled.
Actions
Pick target mode; confirm PM claim submission is turned off (B and C, when markChargeBilled is unsupported); Start ERA enrollment (B); Change mode.
States
Unsupported modes disabled with the reason. Mode B with payers not yet enrolled: those payers run as Mode C until enrollment is active (listed).
Rules
Applies to claims released after the change; in-flight claims finish in the mode they were released in. Admins only. Audited.
