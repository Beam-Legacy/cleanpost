Sign-in and account access

Centered single-column screens on the canvas, with the mark and wordmark at the top. Two-factor is required for every user. No patient information appears on any of these screens.

A-01

Sign in

PageMVPRoute /sign-in
Purpose
Start a session with email and password, or with a passkey.
Data
better-auth credentials; return path from the URL (?next=).
Actions
Sign in (then A-02); Sign in with a passkey (skips A-02, passkeys count as two factors); Forgot password (A-04).
States
Wrong email or password: one generic error under the form ("Email or password is incorrect"), never which one. After 5 failures: A-08. Submitting: button shows progress.
Rules
Rate-limited per IP and per account. Failed attempts logged. No "remember me"; device trust is handled in A-02 if the tenant allows it.

A-02

Second factor

PageMVPRoute /sign-in/verify
Purpose
Confirm the second factor after the password.
Data
User's enrolled factors (authenticator app, passkey); tenant setting for device trust.
Actions
Enter 6-digit code (auto-submits on the 6th digit); Use a passkey instead; Use a recovery code; Trust this device for 12 hours (only if the tenant allows and the device is approved).
States
Wrong code: field error, code cleared, focus returns. 5 wrong codes: A-08.
Rules
One-time-code input uses autocomplete="one-time-code". Recovery code use emails the user and marks the code spent.

A-03

Set up two-factor

PageMVPRoute /setup/two-factor
Purpose
Enroll the required second factor on first sign-in.
Data
TOTP secret and QR (generated server-side); 10 recovery codes.
Actions
Step 1: scan QR or copy the setup key; enter a code to confirm. Step 2: download or copy recovery codes; confirm saved; Continue. Alternative: Add a passkey instead.
States
Wrong confirmation code: field error. Continue disabled until "I saved these codes" is checked.
Rules
Cannot be skipped. Recovery codes shown once; regenerating invalidates the old set (A-09).

A-04

Actions

States

A-05

Reset password

PageMVPRoute /reset-password?token=
Purpose
Set a new password from a reset link.
Data
Reset token; password rules (NIST 800-63B: at least 12 characters, checked against breached-password lists, no composition rules).
Actions
Set password; then sign in (two-factor still required).
States
Expired or used token: message with "Send a new link". Weak or breached password: inline error explaining why.
Rules
Signs out all other sessions and emails the user.

A-06

Accept invite

PageMVPRoute /invite?token=
Purpose
Let an invited user join their billing company's workspace.
Data
Invite: tenant name, inviter, role, client scope summary, email (locked).
Actions
Enter name and password, accept the terms of use; Create account (then A-03). Existing users: "Sign in to accept" adds the membership.
States
Expired invite (7 days): ask the inviter to resend. Already accepted: link to sign in.
Rules
Email cannot be changed. Account is created only after two-factor is set up.

A-07

Choose company

PageMVPRoute /choose-company
Purpose
Pick which billing company to work in, for users with more than one membership.
Data
memberships for the user: tenant name, role, open items assigned.
Actions
Select a company (sets the session tenant); Remember my choice. Also reachable from the user menu (G-05).
States
Skipped for single-membership users. Suspended tenant shown disabled with a reason.
Rules
Switching tenant reloads the app with no data carried over; audit logs the switch.

A-08

Account locked

PageMVP
Purpose
Explain the temporary lock after repeated failed attempts and when it lifts.
Data
Unlock time (15 minutes after the 5th failure); tenant admins.
Actions
Reset password (A-04); Back to sign in.
States
Locked by an admin (deactivated): different copy, no timer, contact admin.
Rules
The user gets an email (E-03 style) about the lock. The page does not confirm whether the email exists to anonymous visitors; it appears only after a valid email was entered.

A-09

Profile and security

PageMVPRoute /account
Purpose
Let users manage their own name, password, sign-in methods and sessions.
Data
users (name, email), two-factor devices and passkeys, recovery codes remaining, active sessions (device, browser, approximate location, last active).
Actions
Edit name; Change password (requires current password); Add authenticator or passkey; Remove a factor (cannot remove the last); Regenerate recovery codes; Sign out a session; Sign out all other sessions.
States
Sensitive changes ask for re-authentication if the last sign-in was over 15 minutes ago.
Rules
Email changes go through an admin. Every change emails the user and is audit-logged.
