Work queue

The biller's home screen. One queue across every client they are assigned to, worked from the keyboard, with a side panel for each kind of work item so most items are resolved without leaving the list.

W-01

Work queue

PageMVPRoute /work
Purpose
Show everything that needs this user, most urgent first, and let them resolve items without leaving the list.
Data
work_items for the tenant, scoped to the user's client scope; joined client, payer, patient (last name, first initial), amount (claim balance or remittance total), reason (work_items.summary), due_at, assignee. Summary strip from reports rollups for today.
Actions
  • Type chips filter by work item type; counts update live.
  • Row click or Enter opens the side panel (W-10 to W-24); J/K move; A approve; E edit; S snooze (W-06); R resolve (W-07); / search; ? shortcuts.
  • Checkbox selection shows the bulk bar (W-04).
  • Save view (W-08); Filters (W-09).
States
Panel open: list switches to the compact two-line layout shown (item and reason; patient, payer and client). Panel closed: full columns as in W-02. Loading: table skeleton (G-20). Nothing due: W-03. Filter returns nothing: inline empty row "No items match these filters" with Clear filters. Panel closed: list takes full width.
Rules
Default sort priority, due time, amount. Due chip: amber within 4 business hours of SLA, red past due. Resolving an item moves focus to the next row. List shows reduced identifiers only.

Side panel variants

One layout per work item type. Every panel has the same frame: status and mode in the head, a "why is this here" line, the facts needed to decide, and one primary action in the footer. Each opens beside the list (W-01) and expands to the full record with the external-link button.

Rules
Each edit writes a corrections row. Release in Mode A releases the charge in the PM; B/C submits via Stedi.
